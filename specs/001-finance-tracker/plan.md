# Технический план: 001-finance-tracker

Основание: spec.md, constitution.md

## 1. Стек

| Слой | Решение | Обоснование |
|---|---|---|
| Рантайм | Node.js 22.5+ | встроенный драйвер SQLite, отсутствие нативных сборок |
| HTTP | Express 4 | минимальный роутинг и middleware |
| БД | SQLite через node:sqlite | ноль внешних зависимостей, файл создаётся миграциями |
| Валидация | zod | декларативные схемы, нормализация входа |
| Пароли | bcryptjs | чистый JS, отсутствие требования компилятора |
| Сессия | jsonwebtoken | stateless, переживает перезапуск сервера |
| Клиент | React + Vite | компонентная модель, быстрая сборка |
| Графики | Chart.js | круговые и столбчатые диаграммы |
| Совместимость | @vitejs/plugin-legacy + browserslist | NFR-002 |
| Стили | CSS с переменными | переключение темы без пересборки |

## 2. Архитектура

route → service → repository → SQLite

- route: приём запроса, применение схемы валидации, формирование ответа
- service: бизнес-правила BR-001..BR-011, транзакции, права доступа
- repository: параметризованный SQL, изоляция по user_id
- middleware: cors, парсинг JSON, аутентификация, 404, обработчик ошибок

## 3. Структура репозитория

server/src/{routes,services,repositories,middleware,validation,utils,db}
client/src/{api,pages,components,store,styles}
specs/

## 4. Ключевые решения

### 4.1 Деньги (NFR-007)
Сумма — INTEGER в минорных единицах. Валюта — TEXT из перечня RUB, USD, EUR.
Экспонента валюты фиксирована: 2 для всех трёх. Преобразование в.major-единицы
выполняется только на границе отображения.

### 4.2 Валюты (FR-001, FR-002, BR-007)
Курс хранится в fx_rates на дату. Пересчёт в основную валюту выполняется
в SQL-агрегате, чтобы не выгружать все операции в память. Основная валюта —
поле настроек пользователя.

### 4.3 Сессия (FR-016, FR-020)
JWT со сроком 7 дней, payload содержит только sub и email. Токен хранится
клиентом и передаётся в заголовке Authorization. Восстановление сессии —
запрос GET /api/auth/me при старте приложения. Тема, валюта и фильтры
хранятся в user_settings и дублируются в localStorage для мгновенного применения.

### 4.4 Переводы (FR-025, BR-003)
Одна запись типа transfer с account_id и target_account_id. Агрегаты доходов
и расходов фильтруют type != 'transfer'. Баланс счёта считается как сумма
income минус expense плюс входящие переводы минус исходящие.

### 4.5 Прогноз (FR-014, BR-008)
Медиана месячных сумм по категории за 3 последних завершённых месяца.
Медиана выбрана вместо среднего из-за устойчивости к разовым крупным тратам.

### 4.6 CSV (FR-013, FR-026)
Разбор на сервере, кодировка UTF-8, разделитель запятая или точка с запятой.
Импорт построчный: валидные строки применяются в одной транзакции, невалидные
возвращаются списком с номерами. Экспорт повторяет активные фильтры.

### 4.7 Совместимость браузеров (NFR-002)
browserslist: chrome >= 60, firefox >= 55, edge >= 79, safari >= 12.
Сборка транспилируется плагином legacy, полифиллы подключаются автоматически.
В CSS не используются :has(), container queries и subgrid.

## 5. Риски

| Риск | Митигция |
|---|---|
| Отсутствие курса валют на дату | последний известный курс + пометка в ответе |
| Расхождение баланса при параллельных переводах | транзакция на уровне БД |
| Рост числа операций и деградация агрегатов | индексы по user_id, date, category_id |
| Утечка секрета | .env в gitignore, в репозитории только .env.example |

## 6. Порядок реализации

Фундамент → авторизация → справочники → операции → бюджеты → аналитика →
импорт/экспорт → отчёты и шаблоны → клиент → приёмочная проверка.
