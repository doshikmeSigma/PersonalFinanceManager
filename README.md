## 1. Общие требования

1. Приложение должно иметь интуитивно понятный интерфейс, адаптивный дизайн с приоритетом на мобильные устройства и обеспечивать удобный доступ к управлению финансами на любых устройствах.
2. Приложение должно поддерживать работу с данными в различных валютах, например:
   - RUB;
   - USD;
   - EUR.
3. Пользователь должен иметь возможность выбрать одну основную валюту для отображения сводной статистики.
4. Приложение должно поддерживать минимально необходимые версии браузеров:

| Браузер | Минимальная версия |
|---|---:|
| Chrome | 60 |
| Firefox | 55 |
| Edge | 79 |
| Safari | 12 |

---

## 2. Функциональные требования

### 2.1. Дашборд и визуализация

1. Пользователь должен видеть дашборд с визуализацией расходов и доходов.
2. Визуализация должна включать:
   - круговые диаграммы;
   - столбчатые диаграммы.
3. Пользователь должен иметь возможность выбирать период анализа.
4. Каждая финансовая операция должна содержать:
   - дату;
   - сумму;
   - категорию;
   - тип операции: доход или расход;
   - необязательный комментарий.
5. Список операций должен быть отсортирован по дате по убыванию.
6. Пользователь должен иметь возможность группировать или фильтровать операции:
   - по категориям;
   - по типам операций;
   - по конкретным счетам, если поддерживается функциональность счетов.

---

### 2.2. Управление финансовыми операциями

1. Пользователь должен иметь возможность добавлять финансовые операции.
2. Пользователь должен иметь возможность редактировать финансовые операции.
3. Пользователь должен иметь возможность удалять финансовые операции.
4. Пользователь должен иметь возможность создавать категории расходов и доходов.
5. Пользователь должен иметь возможность редактировать категории.
6. Пользователь должен иметь возможность удалять категории.
7. Пользователь должен иметь возможность устанавливать лимиты бюджета:
   - на конкретные категории;
   - на общий период.
8. Приложение должно отображать визуальный индикатор приближения к лимиту.
9. Приложение должно отображать визуальный индикатор превышения лимита.
10. Приложение должно поддерживать импорт данных о транзакциях из CSV-файла.
11. Приложение должно формировать простой прогноз расходов на следующий месяц на основе исторических данных.
12. Для прогноза может использоваться расчет среднего арифметического или медианы расходов по категориям за последние 3 месяца.

---

### 2.3. Уведомления

1. Приложение должно предоставлять всплывающую панель уведомлений.
2. Уведомления должны отображаться для следующих событий:
   - успешное добавление операции;
   - успешное удаление операции;
   - успешное редактирование операции;
   - успешное сохранение операции;
   - успешный импорт CSV;
   - превышение установленного лимита бюджета.

---

### 2.4. Сохранение состояния сессии

1. Приложение должно сохранять статус авторизации пользователя.
2. Приложение должно сохранять выбранную валюту.
3. Приложение должно сохранять настройки темной или светлой темы.
4. Приложение должно сохранять последние примененные фильтры.
5. Сохраненные данные должны использоваться при следующем открытии окна или вкладки.
6. Приложение должно возобновлять сессию пользователя при повторном открытии.

---

### 2.5. Отчеты и шаблоны регулярных платежей

1. Пользователь должен иметь возможность формировать пользовательские отчеты.
2. Пользователь должен иметь возможность сохранять сформированные отчеты.
3. Пользователь должен иметь возможность создавать шаблоны регулярных платежей.
4. Пользователь должен иметь возможность редактировать шаблоны регулярных платежей.
5. Пользователь должен иметь возможность удалять шаблоны регулярных платежей.

---

## 3. Дополнительные функциональные требования

### 3.1. Поиск транзакций

1. Приложение может предоставлять поисковую строку для быстрого нахождения конкретной транзакции.
2. Поиск должен учитывать:
   - название;
   - сумму;
   - категорию;
   - комментарий.

---

### 3.2. Поддержка нескольких счетов или кошельков

1. Приложение может поддерживать несколько счетов или кошельков.
2. Примеры счетов:
   - Наличные;
   - Банковская карта;
   - Накопительный счет.
3. Пользователь должен иметь возможность просматривать переводы между счетами.
4. Переводы между счетами не должны искажать общую статистику доходов и расходов.

---

### 3.3. Экспорт данных

1. Приложение может предоставлять возможность экспорта отфильтрованных данных о транзакциях.
2. Поддерживаемые форматы экспорта:
   - CSV;
3. Экспорт должен использоваться для внешнего анализа данных.
